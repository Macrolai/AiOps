Native Kubernetes semantics

按 Kubernetes 的方式，
管理工作负载。

不是把所有资源硬塞进一张通用表格。工作负载、服务、网络、配置和存储各自保留关键列、原生状态与关联操作，日常编辑以结构化表单为主。

  • 覆盖 Deployment、StatefulSet、DaemonSet、Job、CronJob、Pod、HPA、PDB 与 Helm Release。
  • Service 支持 ClusterIP、Headless、NodePort、LoadBalancer、ExternalName 与多端口。
  • 工作负载详情按 Selector 关联 Pod、Service 与 ReplicaSet，故障影响范围可在上下文中定位。
  • YAML 保留为高级路径，创建时提供语法检查与 Kubernetes Server-Side Dry Run。
  • Terminal、日志与端口转发受资源级 RBAC、一次性票据和后端审计约束。
平台权限、kubeconfig 的 Kubernetes RBAC 与云厂商 IAM 同时生效，任一不通过都不能执行。

Scoped by design

权限不是隐藏菜单，
而是贯穿每一层数据。

组织、项目、环境与资源范围同时作用于菜单、路由、列表、详情、AI 上下文和操作创建。直接访问未授权 URL 返回 403，后端 API 也不会依赖前端隐藏来保护数据。

IDENTITY & POLICY 身份、授权与审批收口

JWT 登录与 OIDC / SSO 统一接入，权限绑定支持全局、组织、项目、环境、集群、Namespace 和单资源范围。

默认拒绝显式拒绝优先Break-glass 审计
CHANGE SAFETY变更保护

高风险写操作确认影响范围，生产高风险支持双人审批；变更冻结与 Break-glass 原因进入审计。

SECRETS敏感信息保护

云凭据和回调密钥 AES-256-GCM 加密，Agent Token 仅存摘要，Secret 列表与详情脱敏。

AUDIT操作与终端审计

Terminal、端口转发、RBAC、审批与配置变更保留操作者、目标、结果与时间。

PROJECT SCOPE研发自助不越界

项目成员获得项目范围角色；Node、PV、StorageClass、CRD 与全局 RBAC 不会借项目权限下放。
